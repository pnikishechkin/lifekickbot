## Context

Хранилище уже есть (`storage.py`: `init_db`, `save_workout`, таблица `workout_entries`). Бот пишет тренировки, но никогда их не читает, а каждый ответ LLM получает только текущее сообщение и статичный промпт — ни нити диалога, ни данных. См. proposal.md (Why) для мотивации.

Проект: Python + aiogram + DeepSeek, один процесс локально, stdlib-only хранилище.

## Goals / Non-Goals

**Goals:**
- Бот держит нить диалога с пользователем в пределах окна последних сообщений.
- Бот реально использует сохранённые тренировки: естественно ссылается на них фоном и строит отчёты по запросу.
- Не плодить вызовы LLM сверх минимума.

**Non-Goals:**
- Персистентная история переписки — окно живёт в памяти процесса и теряется при рестарте (решается позже отдельным change).
- Отчёты по другим доменам (еда, вес, сон).
- Проктинные инициативы «сам предложи отчёт без запроса».

## Decisions

### Rolling-окно переписки в памяти
`conversation = defaultdict(deque)` — на каждого `user_id` последние ~20 реплик (роль + текст). Перед формированием ответа добавляем текущее сообщение пользователя, после ответа — ответ бота. При переполнении выкидываются самые старые.
- Альтернатива «хранить переписку в SQLite» отклонена: больше кода и дисковых записей, а реальная ценность контекста — короткая нить диалога; долговременная память — это структурированная история в `workout_entries`, а не сырой текст.
- Ограничение честно отмечено в spec и proposal: рестарт сбрасывает окно.

### Один вызов извлечения распознаёт и намерение
Расширяем существующий промпт `EXTRACT_PROMPT`: вместо только `is_workout` — поле `intent` со значениями:
- `workout` — сообщение о тренировке (как сейчас `is_workout=true`),
- `report` — запрос показать историю,
- `none` — всё остальное.
Плюс `report_period`: `"day" | "week" | "month" | "all" | null` для отчётов.
Один вызов вместо трёх (извлечение + распознавание отчёта + ответ): меньше расходов и задержек. Совместимость: `is_workout` в ответе больше не нужен, ветвимся по `intent`.

### Хранение: новая read-функция
`get_workouts(user_id, since=None, limit=None) -> list[dict]`: строки `workout_entries`, фильтр по `user_id`, опциональный фильтр `performed_at >= since`, сортировка `performed_at DESC`, опциональный `LIMIT`. Та же связь и тот же лок, что у записи.

### Сборка контекста для ответа
Сообщения в `ask_deepseek` собираются как:
```
[system: system_prompt.txt]
[system: сводка данных из истории]   ← дайджест (для любого ответа)
...реплики из окна переписки...      ← нить диалога
[user: текущее сообщение]
```
- **Дайджест (всегда фоном):** последние `N=5` тренировок пользователя, компактно: `2026-09-21 — силовая (жим 80)`. Если записей нет — строка «тренировок пока нет», чтобы LLM не выдумывал. Для `report`-ветки дайджест заменяется полной выборкой за период.
- **Отчёт по запросу (`intent == "report"`):** период → `since` в UTC → `get_workouts(user_id, since=...)` → полный список передаётся в тот же ответный вызов, LLM рассказывает в характере. Пустая выборка → бот честно говорит «пусто».

### Ветвление в `ai_handler`
```
extract → intent:
  workout → save_workout (как раньше) → обычный ответ с дайджестом
  report  → выборка за период → ответ по данным
  else    → обычный ответ с дайджестом
```
Ветка «извлечение упало / мусор» — как раньше: сохраняем старые ветки без данных.

### Промпт
`system_prompt.txt`: добавляем правило — в ответах про историю/статистику опираться только на предоставленные в сообщении от пользователя данные и «сводку», ничего не додумывать.

## Risks / Trade-offs

- **LLM приукрасит цифры из сводки** → инструкция «опирайся только на данные» + сводка компактна. Полный контроль невозможен, но цена ошибки — неверная шутка, не данные.
- **Окно в памяти теряется при рестарте** → заявленное ограничение; структурная история в SQLite не страдает, именно ей и пользуются отчёты.
- **Токены входа растут** → окно ограничено 20 репликами, дайджест 5 записей; DeepSeek контекст большой, для текущего масштаба некритично.
- **Продолжение фразы без субъекта** («и присел 100») — извлечение может посчитать такую фразу тренировкой без контекста → в ветке `workout` сохраняем только то, что сообщено; риск лишней записи, приемлемо для этой версии.

## Migration Plan

Ревью-деплой на работающий бот: остановить, обновить `storage.py`, `bot.py`, `system_prompt.txt`, запустить. Существующая БД и схема не меняются (только новая функция чтения). Откат — вернуть прежние файлы; окно и отчёты просто перестанут работать, ничего не сломается.

## Open Questions

- **Период по умолчанию для отчёта без указания периода** — «последние 7 дней»? Или «все тренировки»? Настройка константой, меняется позже. Не влияет на схему спека.
- **Часовой пояс в отчётах** («за неделю» в понятном пользователю смысле) — по-прежнему UTC, выбор пояса командой — отдельный change.
