## Context

См. proposal.md — Why. Текущее состояние: бинарный `bot.py` (aiogram 3.31, openai 3.6.0, python-dotenv 1.2.3) содержит `SYSTEM_PROMPT` строкой в коде, не валидирует токены, вызывает DeepSeek напрямую с `message.text` (без guard для не-текста) и без обработки ошибок. Уже установлена библиотека `python-dotenv`.

## Goals / Non-Goals

**Goals:**
- Промпт как отдельный редактируемый файл, загружаемый при старте.
- Понятные ошибки при старте, если конфигурация неполная.
- Корректное поведение на не-текстовые сообщения и ошибки LLM.
- Минимальные изменения в структуре модуля (один файл `bot.py`).

**Non-Goals:**
- Разделение на пакеты/модули, логгер на уровне приложения.
- Кэширование промпта с перезагрузкой в рантайме (перезагрузка = перезапуск бота).
- Обработка фото еды и других интеграций (v2 по README).

## Decisions

- **Загрузка промпта через `Path`**: `Path(__file__).parent.joinpath("system_prompt.txt").read_text(encoding="utf-8")` на этапе импорта модуля, чтобы отказ произошёл в момент старта (а не в первом хендлере). UTF-8 обязателен — промпт на русском.
  - *Альтернатива*: читать лениво в каждом запросе — хуже: лишний I/O и отказ придет позже старта.
- **Валидация токенов** сразу после `load_dotenv()`: проверить `TELEGRAM_TOKEN` и `DEEPSEEK_API_KEY` на пустоту, при ошибке `raise SystemExit` с сообщением о недостающем ключе.
  - *Альтернатива*: позволить aiogram/DeepSeek падать своим непонятным трейсбеком — отклонено, противоречит spec.
- **Guard на текстовое содержимое** в `ai_handler`: если `message.text` отсутствует (фото/стикер/голос/документ) — сразу `message.answer("Пока я читаю только текст...")` без вызова LLM.
  - *Альтернатива*: фильтр aiogram по типу контента — избыточно, один guard проще и покрывает все не-текстовые ветки.
- **Обработка ошибок LLM**: `try/except Exception` вокруг `client.chat.completions.create` в `ask_deepseek` + вокруг `message.answer` в `ai_handler`, с `print` (пока нет логгера) и fallback-ответом. Пустой `content` ответа трактуется как ошибка.
  - *Альтернатива*: `logging` модуль — не добавляем, размер изменения мал; `print` достаточно для диагностики на этом этапе.

## Risks / Trade-offs

- Промпт читается при импорте → если файл добавить позже запуска, нужен рестарт. → Задокументировано в README/файле; старт падает с явной ошибкой, а не молча работает без промпта.
- `except Exception` может прятать ошибки. → Ошибка логируется перед fallback-ответом; пустой ответ по-прежнему валится в fallback.
- Удаление `SYSTEM_PROMPT` из кода — diff в git легко слить повторно случайно. → Новый файл `system_prompt.txt` идемпотентен, содержимое переносится без изменений.

## Migration Plan

1. Создать `system_prompt.txt` с текущим текстом промпта (без тройных кавычек).
2. Обновить `bot.py` (загрузка промпта, валидация, guard, try/except).
3. Запуск: `venv/bin/python -m py_compile bot.py` для проверки синтаксиса.
4. Откат: `git checkout bot.py` + удаление `system_prompt.txt` — поведение возвращается к inline-промпту.
